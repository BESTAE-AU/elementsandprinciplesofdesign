
# Design experimentation and development

Experiments are only informative when **one thing changes at a time**, and only useful when they answer a **stated design question**. This guide plans and records that process for any element or principle. The shared method is in `method/experimentation.md`. Each `<element>-element-of-design` skill lists that element's variables.

## Workflow

1. **Write the design question.**
   - Good: "Which stroke weight keeps the logo readable at 16 px and in embroidery?"
   - Weak: "Which logo is best?"
2. **Make a baseline** version.
3. **Choose one variable** from the relevant element's Variables table, such as stroke weight, value contrast, spacing or duration.
4. **Make at least three clearly different versions** of that variable. Hold everything else constant.
5. **Test in realistic conditions:** actual size, actual medium, actual distance or device, and actual users if possible. Screens hide problems that print, stitching, cutting and small sizes reveal.
6. **Record what you observe,** not what you hoped.
7. **Compare against explicit criteria** from the brief.
8. **Select or combine,** and record the trade-off.
9. **Refine:** say what the next single change should be, and why.

## Choosing the method

| Method | Best for |
|---|---|
| Thumbnails and sketches | Fast exploration of many options |
| Mock-ups in context | Checking how a design looks on a cup, wall, phone or garment |
| Prototypes | Physical or functional questions (grip, fit, strength, interaction) |
| Proofs and test prints | Colour, line weight and small-size reproduction |
| User testing (e.g. a five-second test) | Whether people find, read or understand something |
| Decision matrix | Only when criteria are clear enough to justify scores |

## For brands

Extend surviving options to at least three touchpoints. Test the smallest and largest sizes, reversed and monochrome versions, and record what breaks away from the logo (`method/experimentation.md`, `brand-system-testing.md`).

## Common weaknesses

- Random variations with no question.
- Changing several variables at once.
- Testing only on screen.
- Development pages that show versions but no observations.
- A "best" version chosen by preference.
- No trade-off recorded.

## Teaching ideas

- **One-variable challenge:** each student gets one variable and must make three versions.
- **Real-size test day:** print or produce every version at real size and test.
- **Five-second test:** show versions for five seconds and record what people noticed.
- **Development page model:** annotate an exemplar page showing question → versions → observations → decision.
