# Unity — principle of design

This skill covers **unity** as a principle of design. Principles describe relationships and organisational effects; elements (line, direction, shape, form, space, size and scale, time and duration, value, colour, texture, typography, layout and composition) are the variables that create them. So always explain *which elements* produce unity and *how*, and never treat an element and a principle as the same thing.

The shared method (analysis progression, justification levels, Factors Affecting Design, experimentation, teaching resources, feedback and marking, and language rules) is in the shared method files. For depth on a particular element, use its `<element>-element-of-design` skill. For whole-process help, use the method skills (`design-analysis-progression`, `design-justification-writing`, `design-feedback-and-marking`, and so on).

## What unity is

Unity is the sense that all parts of a design belong together and form one coherent whole.

Keep it distinct:
- **Unity vs harmony:** harmony is how pleasingly elements relate; unity is whether they read as one whole.
- **Unity vs uniformity:** unity can include variety; uniformity is everything identical.
- **Unity vs repetition:** repetition is one way to create unity.

## Types and variations

- **Visual unity:** shared colours, shapes, type.
- **Conceptual unity:** a shared idea or theme.
- **Unity through proximity and alignment.**
- **Unity through continuation:** lines or edges that carry across.
- **System unity:** consistency across a series or brand.

## Levers: what a designer changes to create unity

- Limited palette
- Consistent type
- Repeated shapes and devices
- Alignment and grid
- Proximity
- Shared concept

## Common misconceptions

| Misconception | Better understanding |
|---|---|
| "Unity means everything looks the same." | Unity with variety is usually stronger. |
| "Adding more elements makes it richer." | Each unrelated element weakens unity. |
| "Unity is only visual." | A shared concept can unify very different visuals. |

## Worked analysis (model for exemplars and annotations)

Scenario: A student's folio: every page uses the same 12-column grid, one sans-serif family, a three-colour palette and a thin rule under each heading.

- **Identify:** "The design uses unity."
- **Describe:** "Consistent grid, one typeface family, three colours and a repeated rule across every page."
- **Explain:** "The repeated system makes the folio read as one body of work."
- **Analyse:** "Unity comes from repetition and alignment, with variety provided by changing images and layouts within the grid."
- **Evaluate:** "Effective for a folio that needs to read as one project. However, identical page structures make the development section hard to tell apart from the final; a distinct colour accent for 'final' pages would keep unity while signposting."

Each level should add a link in the chain, not simply more words.

## Justification examples

- **Weak:** "I made it match."
- **Developing:** "I used the same font and colours on every page."
- **Strong:** "I used one grid, one type family and a three-colour palette on every page so the folio reads as one project, while images and layouts vary within the grid."
- **Sophisticated:** "After peer review, readers couldn't tell development pages from final pages. I added a fourth accent colour only for final pages, slightly weakening the palette's simplicity but making the structure clearer."

## Feedback patterns to look for in student work

- **Too many typefaces or colours.**
- **No shared grid** across pages.
- **Unity confused with sameness.**
- **Elements that don't relate** to the concept.

## Activity ideas for teaching resources

- **Odd one out:** remove the element that breaks unity from a design.
- **Unify a mess:** unify five unrelated flyers using only type and colour rules.
- **Series design:** make three posters that are clearly one series but not identical.
- **Folio audit:** check a folio for consistent grid, type and colour.
