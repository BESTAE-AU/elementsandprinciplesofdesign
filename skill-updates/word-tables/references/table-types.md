# Table Types

Before sizing a table, name its **job**. The job decides the structure, which
column gets the width, and usually the orientation. Most workbooklet tables are
one of the types below.

## Is a table the right tool?

Use a table when the information has **two dimensions**: items that share the
same set of attributes (terms × definition × example, criteria × grade levels).

Don't use a table for:

- a simple list with one attribute, such as a list of materials (use a list);
- a single block of writing space (use `Writing Lines`);
- a sequence where each step needs extended explanation or a large image (use
  numbered headings and paragraphs);
- positioning content on the page, unless it is a deliberate layout table (see
  `styling.md`, Accessibility).

## Catalogue

| Type | Job | Typical structure | Width goes to | Usual orientation |
|---|---|---|---|---|
| **Comparison** | Show how 2–4 things differ on the same attributes | Attribute label column + one column per item | Item columns, equally | Portrait for 2–3 items; landscape for 4+ or with images |
| **Classification** | Sort items into named groups | Vertical category column + item + description | Description | Portrait |
| **Process / sequence** | Show ordered steps | Step number + step + key point (+ image) | Step description | Portrait |
| **Rubric / matrix** | Describe performance at several levels | Criterion column + one column per level | Level columns, equally | Landscape for 4+ levels; `MARKING CRITERIA` style for marks + criteria |
| **Response / worksheet** | Collect student answers | Prompt column + response column(s) | Response columns | Portrait |
| **Reference / glossary** | Look things up | Term + definition (+ example) | Definition | Portrait, even when long |
| **Image comparison** | Compare visual examples | One column per image, rows for analysis | Image columns, equally | Landscape for 3+ images |
| **Specification** | List properties of one or more products | Property label + value column(s) | Value columns | Portrait; landscape for several products |

## Structure notes by type

**Comparison**
- Put the items being compared across the top and the attributes down the side.
  Students read across a row to compare, which is the point of the table.
- Keep the item columns equal, so no item looks more important.
- Pick a width where they divide into whole centimetres: 3 items → 18 cm
  (6 + 6 + 6) portrait, or 27 cm (9 + 9 + 9) landscape. With a label column:
  19 cm = 4 + 5 + 5 + 5.

**Classification**
- Groups become vertical category columns, or Pale group rows with Heading 5 if
  there are more than about 4 groups.
- Order the groups the way the unit teaches them.

**Process / sequence**
- The step number column is 1.5 cm (the numbers minimum).
- If each step needs a large image, use landscape with an image column, or drop
  the table and use headings and paragraphs.

**Rubric / matrix**
- For the school's A–E scale, use the `marking-rubric-builder` skill for the
  content. This skill sizes the table.
- Level columns are equal. Order them from highest to lowest, left to right (A
  to E), unless the task or faculty convention says otherwise.
- The simple marks + criteria rubric (the `MARKING CRITERIA` table style) is
  portrait: 3 + 16 cm at 19 cm.

**Response / worksheet**
- Give most of the width to the response columns: prompt 4–6 cm, response the
  rest.
- Size response rows by the response type (see `styling.md`, Student response
  space).

**Reference / glossary**
- The term column is only as wide as the longest term needs on two lines,
  typically 3–4 cm.
- Stays portrait even when long. Paginate with repeated header rows and letter
  or topic group rows.

**Image comparison**
- Images across the top in equal columns, and analysis rows below.
- Use edge-to-edge images with a common crop (see `styling.md`, Images in
  tables).
- Put the response row last, so students see everything before they judge.

**Specification**
- The property label column is 3–5 cm.
- Put units in the header or the label (for example "Width (mm)"), not repeated
  in every cell.
