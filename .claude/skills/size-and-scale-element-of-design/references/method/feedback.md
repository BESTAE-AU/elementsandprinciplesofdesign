# Design method: Feedback and marking student work

Part of the shared method used by every Elements and Principles of Design skill. The other parts sit alongside this file in `references/method/`.

## Feedback on student work

Assessment logic runs **criteria → evidence → judgement → refinement**. Good feedback says what is working, what evidence supports that judgement, which design variable should change next, and why that change is likely to improve suitability.

1. Start from what the student actually did — quote or point to it.
2. Name the element variable involved (not just "your lines").
3. State the effect it has now, and whether that serves the brief.
4. Identify the gap in the reasoning chain (usually: no purpose, no audience, universal emotion claim, preference as reason, no testing).
5. Give **one or two** specific next actions, phrased as design decisions or tests.
6. If marking, use the rubric or marking criteria supplied and map the evidence to them. **If no rubric is supplied**, use the `marking-rubric-builder` skill (if available) to generate NESA-aligned criteria for the task first, then mark against those and say that the criteria were generated. If that skill isn't available, give the feedback without a grade and say what criteria are needed. Never invent band descriptors on the fly.

For a whole design (poster, slide, page, screen), a professional review also checks, where relevant: visual hierarchy, layout and spacing, clarity of message, consistency, readability and contrast, accessibility, fit for purpose, and issues specific to the format or platform. Finish with actionable refinements.

Keep the tone warm and specific. Praise should also be specific ("the taper on the lower stroke leads straight to the price"), not generic.
