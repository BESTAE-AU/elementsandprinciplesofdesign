# Portfolio and project evidence

Use this guide for folios, major projects, development documentation, portfolio audits and progress reports.

A portfolio is an evidence trail that makes decisions traceable, not a polished retrospective publication.

**Need → brief → research → criteria → alternatives → selection → tests → refinement → production → evaluation.**

## Core evidence

Situation and need, purpose, audience, brief, criteria and specifications, research with implications, initial ideas, developed concepts, annotated comparisons, trials, feedback, changes made, production plans, time and cost records, quality checks, final evaluation and reflection.

Projects need different evidence, so don't impose a page count the task doesn't set. A failed sample with clear analysis is valuable evidence. Ask of every page: what part of the design process does this demonstrate?

## Documentation habits

- Label versions, dates and purpose. Photograph meaningful stages with explanations.
- Separate what was planned from what happened.
- Explain research implications and design changes. Use the decision record in `design-process.md`.
- Cite sources and disclose permitted assistance, including AI, as the assessment requires.
- Annotation links features to effect and suitability; evaluation compares results with criteria; reflection names learning and future practice.

## Auditing a portfolio

An audit should be repeatable against the current task, rubric and actual files. Track student, submission version, evidence location, status, provisional criterion judgement, missing evidence and next steps.

| Status | Meaning |
|---|---|
| Complete | Required evidence available and sufficient for the check |
| Partial | Some relevant evidence; a requirement is unresolved |
| Missing | Not found in the material supplied |
| Inaccessible | The file or link couldn't be opened |
| Not yet assessed | Available but not yet judged |

Never treat inaccessible as missing, or missing as proof the student did no work. Record scope and uncertainty. Quote or locate actual evidence; don't infer motives, invent pages or claim an official grade.

## Progress reports and dashboards

Show dated progress, evidence gaps, priorities and changes since the last review. Completion percentage is not achievement quality, and a mark must trace to rubric evidence (use `marking-rubric-builder`). Student or parent reports can list completed requirements, remaining work, a provisional level where justified, strengths and concrete next steps. Britt's preferred level terms: elementary, basic, sound, thorough, extensive.

Save reports in a clearly named project folder when asked, using verified student names. Preparing a report doesn't authorise sending it: recipients and sending need an explicit request.

## Teaching

Teach evidence collection throughout the project, not at the end. Support with a milestone map and sample annotations; extend through independent criteria, stronger comparisons and critical reflection. Protect student information and use approved systems for identifiable work.
