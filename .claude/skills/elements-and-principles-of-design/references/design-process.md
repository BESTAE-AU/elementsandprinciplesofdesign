# Design process and decision-making

Use this guide for briefs, criteria, research, ideation, alternatives, selection, prototyping, testing, refinement, evaluation and production planning in any TAS or design project. Justification writing is in `design-justification-writing.md`, Factors Affecting Design in `factors-affecting-design.md`, and portfolio evidence in `portfolio-and-evidence.md`.

**Key rule:** stages are landmarks, not one-way gates. Real development loops: investigate ⇄ define ⇄ generate ⇄ prototype ⇄ test ⇄ refine. A linear model (investigate → design → produce → evaluate) is fine for novices, provided earlier decisions can still change.

## Reasoning structures

| Purpose | Chain |
|---|---|
| Problem framing | Situation → need → purpose and context → brief |
| Research | Finding → what it means → what should change |
| Criteria | Need → requirement → criterion → test method |
| Ideation | Diverge → develop → compare → converge |
| Selection | Alternatives → criteria → comparison → trade-off → selection |
| Testing | Question → variable → trial → evidence → interpretation → decision |
| Refinement | Problem → evidence → probable cause → variable changed → expected effect → retest |
| Evaluation | Criterion → evidence → judgement → limitation → improvement |
| Traceability | Need → research → criteria → design → testing → decision → evaluation |

## Key ideas, stage by stage

- **Brief.** Defines the challenge, purpose, users and boundaries but leaves real decisions open. Requirements say what the solution must achieve; criteria judge success; specifications are precise enough to make or verify; constraints set limits (time, cost, safety, equipment, materials).
- **Research.** Ask "what decision will this help make?" Primary research is generated by the student (interviews, observation, measurement, material tests, disassembly); secondary uses existing sources. Each important finding needs an identifiable design implication. Example: users wear gloves, so fine fingertip controls will be hard to use, so explore larger controls.
- **Ideation.** Alternate divergent thinking (what else could work? what if the material, scale or interaction changed?) with convergent thinking (criteria, evidence, feasibility). Alternatives must differ meaningfully in structure, form, mechanism, layout, material, interaction or process, not the same idea in three colours.
- **Initial idea → developed concept → final design.** "Final" means currently selected for production. Production can still reveal new information.
- **Selection.** Decision matrices make reasoning visible but are not objective truth: scores are judgements, weights can be arbitrary and precision can be false. Weights should come from the brief, user and evidence (safety may outweigh novelty).
- **Prototyping.** Use the lowest fidelity that answers the question (paper mock-up, cardboard model, toile, wireframe). High fidelity too early wastes time and builds attachment to weak ideas.
- **Experimentation.** Meaningful when one variable is isolated or compared. See `design-experimentation.md`.
- **Feedback.** Evidence, not an instruction. Weigh relevance, expertise, representativeness and fit to criteria. Users often identify a problem without knowing the best fix.
- **Iteration.** Each change needs a reason, and improvement has diminishing returns against time and cost.
- **Evaluation.** Happens throughout, not only at the end. Final evaluation asks: effective for what, according to what evidence, for whom, under what conditions? Use criteria-based, comparative or user-based approaches.
- **Production planning.** Design and production capability shape each other. Plan sequence, tools, materials, time, skills, tolerances, costs, safety and quality checkpoints. Quality assurance prevents failures through process; quality control finds them through inspection and testing.
- **Decisions under uncertainty.** Label decisions exploratory, provisional or committed so early choices don't harden too soon.
- **Changing criteria.** Criteria may change when investigation reveals misunderstood needs, infeasibility, risk or new resources. Document and justify the change. Reframing can change the solution: "students forget equipment" may be a storage and routine problem, not a poster problem.
- **Constraints.** Ask "given this restriction, what becomes possible?" Innovation = novelty + relevance + feasibility or value.
- **Fixation.** Signs: one detailed idea, superficial alternatives, retrofitted justification. Causes include first-idea attachment, copying exemplars, early high-fidelity prototypes and initial AI outputs. Counter with deliberate variation, analogy, changed constraints and delayed selection.
- **AI-assisted design.** AI can generate alternatives and visualisations, but the designer still defines the problem, checks evidence, feasibility, originality and ethics, and makes the decision. AI generation is not justification.

## Common trade-offs

Cost ↔ quality · weight ↔ durability · complexity ↔ usability · novelty ↔ familiarity · customisation ↔ production efficiency · precision ↔ production time · sustainability ↔ upfront cost · aesthetics ↔ function · flexibility ↔ consistency. A trade-off is a balance in context, not a choice of one side.

## Common failure modes and misconceptions

| Weakness | Better approach |
|---|---|
| Starting with appearance before need and purpose | Frame the need first, so the rationale isn't retrofitted |
| Research as background information | Link each finding to an implication |
| Criteria written after the design was chosen | Derive criteria from need, research and brief |
| Testing without a question, or without a change | State what the trial answers and what it changed |
| "Testing proves it works" | Testing produces evidence that needs interpreting |
| "User preference decides" | Weigh preference against safety, function and context |
| Completing pages rather than recording decisions | Ask of each page what part of the process it evidences |
| Endless iteration | Weigh improvement against time and resources |

Process quality and outcome quality are related but separate. A failed prototype with strong analysis (what failed → why → evidence → learning → change) can show more than a polished untested artefact. Evaluation asks how successful the design was; reflection asks what the designer learned.

## Weak → sophisticated (design development)

- Weak: "I made the handle bigger."
- Developing: "I made the handle bigger so it would be easier to hold."
- Strong: "User trials showed insufficient clearance for a comfortable grip, so the internal height was increased."
- Sophisticated: "Users with larger hands couldn't get clearance. Internal height was increased while keeping wall thickness. The prototype needs retesting because the larger opening may reduce stiffness."

## Annotation ladder

Weak "Zipper" → better "Concealed zipper" → stronger "A concealed zipper keeps a clean silhouette while allowing the garment to open" → sophisticated "A concealed centre-back zipper keeps the front silhouette uninterrupted and gives enough opening for dressing; it suits the brief better than a front fastening because a clean costume profile is the priority."

## Teaching and differentiation

| Stage of learner | Task |
|---|---|
| Novice | Choose between provided alternatives and give a reason |
| Developing | Generate alternatives and compare against supplied criteria |
| Competent | Develop criteria from research and evaluate alternatives |
| Advanced | Weight criteria, identify trade-offs, challenge assumptions, test and justify refinement |

Support: teacher-selected sources, partly completed comparison tables, fewer alternatives, sentence starters, oral explanation, modelling. Extension: competing constraints, weighted matrices, stakeholder conflict, ambiguous briefs, lifecycle analysis. Keep the decision-making itself in both.

Process complexity by level: introductory (need → idea → make → evaluate); developing (situation → research → criteria → alternatives → selection → production → evaluation); strong adds user investigation, prototyping and iterative testing; sophisticated adds reframing, stakeholders, weighted conflicting criteria and systems consequences.

## Discipline notes

| Discipline | Typical decisions |
|---|---|
| Product / industrial | Users, form, mechanisms, materials, manufacture, tolerances, ergonomics, safety, maintenance |
| Textiles / fashion | End use, wearer, comfort, movement, silhouette, fabric properties, construction, fit, care |
| Graphic design / branding | Purpose, audience, hierarchy, type, colour, imagery, format, reproduction, accessibility |
| Multimedia / video | Platform, interaction, media types, resolution, compression, pacing, shot choice, sound |
| UI/UX | Need → information architecture → wireframe → prototype → usability test → refinement |
| Interiors / spatial | Circulation, zoning, anthropometrics, lighting, materials, acoustics, access |
| Visual Arts | Conceptual investigation and reflection; keep disciplinary distinctions from design problem-solving |

Time-based design adds sequence, timing, pacing, transitions and audio sync. Test the experience over time, not single frames.
