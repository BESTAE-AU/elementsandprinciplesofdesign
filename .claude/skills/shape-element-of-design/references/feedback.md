# Shape: feedback and marking

Use this file when a teacher shares student work or a justification and wants feedback, a mark or "what gets them to the top band" on shape.

## Workflow

1. **Read the work against its brief.** Note the audience, purpose and every touchpoint or output named (cups, embroidery, a phone screen, signage…). Reproduction problems usually hide there.
2. **Start from what the student actually did.** Quote their words or point to the part of the design, and name the shape variable involved (Variables in `SKILL.md`).
3. **Check for the patterns below** and the misconceptions in `knowledge.md`.
4. **Check production and accessibility.** Use the production table in `knowledge.md` and `method/checks-and-language.md`.
5. **Place the reasoning on the justification ladder** (weak → developing → strong → sophisticated; `method/justification.md`). Say which link in the chain is missing.
6. **If marking:** use the rubric supplied. If none is supplied, use `marking-rubric-builder` (if available) to generate NESA-aligned criteria first, mark against them and say they were generated. Without that skill, give feedback without a grade (`method/feedback.md`).
7. **Write it up:**
   - **What's working:** specific, not generic.
   - **What's holding it back:** 2–4 points, each quoting the student.
   - **Next steps:** one or two, phrased as tests or design decisions, in priority order.
   - **Model structure** (optional): a fill-in-the-blanks version of a top-level justification, with a note not to copy the numbers.
   - **Teacher notes:** current level, gap to the top, and a conferencing question.

Keep the tone warm, honest and specific.


## Feedback patterns to look for in student work

- **Negative space ignored** — the student describes only the figure.
- **Shape and form confused** in written analysis.
- **Fixed personality claims** ("triangles are dangerous") without context.
- **Inconsistent shape language** across an icon set or brand (mixed corner radii, mixed geometry).
- **Detail that won't survive** small size, cutting or embroidery.
- **Boolean slivers** — tiny leftover fragments from overlapping shapes.

## Justification examples (Year 11 app icon set)

- **Weak:** "I used rounded shapes because they look nice."
- **Developing:** "I used rounded squares for all icons so they look friendly and match."
- **Strong:** "I set every icon inside a rounded square with the same 8 px corner radius, so the set reads as one family and matches the rounded buttons in the app. That suits a study app for younger teens who need to recognise icons quickly."
- **Sophisticated:** "I tested sharp-cornered, 8 px and fully circular containers at 24 px. Circles cropped the detail in the calendar and calculator icons; sharp corners clashed with the app's buttons. The 8 px radius kept detail and matched the UI, so I set it as the rule. I gave up the extra distinctiveness of circles for clearer icons."
