# Claude knowledge-base collection

Prepared 30 September 2026. Australian English.

## What this collection contains

Forty master-topic Markdown files, a topic index, preserved plugin-source text references, a source register and the original topic list. The existing Design Process, Elements and Principles files are preserved. Typography, Colour and Layout draw on the existing master. Other files synthesise accessible plugin instructions, established subject knowledge and targeted primary-source checks; selected files include attributed disciplinary extracts for depth.

The files vary in length. The existing Elements and Principles documents are extensive; newer topics provide structured foundations and applied reasoning. This is coverage of all forty master topics, not a claim of exhaustive coverage of every subtopic or a complete export of hidden GPT training/knowledge files. The plugins expose instructions, not all original uploaded university readings, school programs or GPT knowledge attachments.

## How to use with Claude

Start with the index. Supply the smallest relevant topic files alongside the actual project/task, rubric, syllabus or reference. Use the whole collection as a reference repository, rather than inserting every file into each prompt.

These are knowledge bases, not installable skills. There are no trigger definitions, skill metadata or executable agent permissions in the new topic files. Existing source documents and reference copies retain their original instructional phrasing for provenance.

## Evidence categories

- Established user preferences: specific formatting, terminology and brand choices available in this conversation and plugins.
- Accessible plugin instructions: preserved in the references folder and synthesised where relevant.
- Existing knowledge bases: inherited source content; preserved material has not been independently fact-checked in full.
- General subject knowledge: conceptual synthesis, examples and teaching applications.
- Targeted verified guidance: current primary sources for selected curriculum transitions, accessibility, AI guidance, software documentation and protocols.

No inaccessible reading is claimed as consulted. MCCNS's accessible instruction file is effectively empty. It does not establish school policies, marking rules or templates.

## Shared reasoning

Design: decision → evidence/property → effect → purpose/user/context → suitability.

Research: finding → implication → decision.

Selection: alternatives → criteria → comparison → trade-off → selection.

Testing: question → trial/prototype → evidence → interpretation.

Refinement: problem → evidence → cause → change → expected effect → retest.

Evaluation: criterion → evidence → judgement → limitation → improvement.

Teaching: intended learning → prior knowledge → model → guided practice → evidence → adaptation → independent transfer.

Assessment: outcome → evidence → task → criterion → judgement → next action.

## Important distinctions

Elements are manipulated variables; principles describe relationships. Aesthetic meaning is contextual. User preference is evidence, not an automatic instruction. A project file is not necessarily a complete deliverable. Completion is different from achievement. Inaccessible evidence is different from missing evidence. Verification is different from validation. A knowledge base is different from a skill.

Official outcomes, policy, software menus, platform specifications, licences, safety procedures and machine settings need the actual current authority before application. Publication years are not implementation years. Brand preferences are not statutory curriculum requirements or accessibility guarantees.

## Navigation and duplication

Several topics overlap intentionally: colour and typography are included in the Elements master and also supplied separately. Attributed element-specific extracts appear in relevant disciplinary topics. Choose either the master or the focused files to avoid unnecessary duplicate context. Relative links work within the extracted ZIP folder.
